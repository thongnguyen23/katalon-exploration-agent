## <a id="id_3" class="anchor_top_offset"/>Define steps


### <a id="id_4" class="anchor_top_offset"/>Step definitions

<p xmlns="http://www.w3.org/1999/xhtml" className="p">After you added your feature files, you need to define and link steps before using the feature files. </p> 
<p xmlns="http://www.w3.org/1999/xhtml" className="p">Each Gherkin step in the feature files needs to be defined as a set of programming code so that <span className="ph">Katalon Studio</span> can execute the action of that step. These step definitions can be implemented in the <span className="ph uicontrol">Keyword</span> folder by leveraging the <span className="ph uicontrol">Script Mode</span>. </p> 
<p xmlns="http://www.w3.org/1999/xhtml" className="p"><span className="ph">Katalon Studio</span> built-in keywords can also be re-used in <span className="ph uicontrol">Step Definition</span> files as well. When <span className="ph">Katalon Studio</span> executes any feature files in a test case, it also looks for the matching step definitions in the source folder.</p> 
<p xmlns="http://www.w3.org/1999/xhtml" className="p"><span className="ph uicontrol">Step Definitions</span> can be written in any Cucumber-supported programming languages, including Groovy and Java.</p> 
<p xmlns="http://www.w3.org/1999/xhtml" className="p">For example, for two scenario outlines (Login with a valid credential and login with an invalid credential), there are six (6) steps defined as shown below:</p>

### <a id="id_5" class="anchor_top_offset"/>Set the default package for step definitions

<div xmlns="http://www.w3.org/1999/xhtml" className="note important note_important"><span className="note__title">Important:</span> <ul className="ul"><li className="li">Starting with Katalon Studio 9.0.0 and later, setting the default package for step definitions is required.</li></ul></div>
<p xmlns="http://www.w3.org/1999/xhtml" className="p">To help Cucumber locate the step definitions file, you can use the <code className="ph codeph">CucumberKW.GLUE</code> keyword. The default value of <code className="ph codeph">CucumberKW.GLUE = ['']</code> is all packages, which means the test engine takes time to scan through all packages. To speed things up, you can specify the package locations, for example, <code className="ph codeph">CucumberKW.GLUE = ['package1', 'package2']</code> to narrow down where to find the step definitions.</p> 
<p xmlns="http://www.w3.org/1999/xhtml" className="p">We recommend putting the script declaring the package in a test listener.</p> 
<pre xmlns="http://www.w3.org/1999/xhtml" className="pre codeblock"><code>import com.kms.katalon.core.annotation.AfterTestCase{"\n"}import com.kms.katalon.core.annotation.BeforeTestCase{"\n"}import com.kms.katalon.core.context.TestCaseContext{"\n"}import com.kms.katalon.core.cucumber.keyword.CucumberBuiltinKeywords as CucumberKW{"\n"}{"\n"}class NewTestListener {"{"}{"\n"}{"    "}@BeforeTestCase{"\n"}{"    "}def beforeTestCase(TestCaseContext testCaseContext) {"{"}{"\n"}{"        "}CucumberKW.GLUE = ['package1', 'package2']{"\n"}{"    "}{"}"}{"\n"}{"}"}{"\n"}</code></pre> 
<div xmlns="http://www.w3.org/1999/xhtml" className="p">Starting Katalon Studio 9.0.0 and later, for BDD projects created in version 8.x to work as before, you also need to include the following <code className="ph codeph">@BeforeTestCase</code> listener:<pre className="pre codeblock"><code>@BeforeTestCase{"\n"}def beforeTestCase(TestCaseContext context) {"{"}{"\n"}{"  "}CucumberGlueGenerator.addDefaultPackages();{"\n"}{"}"}</code></pre><div className="note note note_note"><span className="note__title">Note:</span> <ul className="ul"><li className="li"><p className="p">The glue should be assigned to the step definition packages of the feature files, not the packages of the Cucumber runner.</p></li><li className="li"><div className="p">If the glue is incorrectly set to the runner package (such as <code className="ph codeph">glue="com.vv.sailorApp.Runners"</code>), the test may pass but no steps will be run. To fix this, ensure the glue points to the correct step definition packages, for example:<pre className="pre codeblock"><code>glue = ['com.vv.sailorApp.StepDefinitions', 'otherStepDefinitionPackages']</code></pre></div></li><li className="li"><div className="p">Make sure all Cucumber hooks, such as <code className="ph codeph">@Before</code> and <code className="ph codeph">@After</code>, are placed in the correct step definition folders. For example, move all the hooks from the files <code className="ph codeph">Test Listeners/SetupTestListener</code>, <code className="ph codeph">Keywords/com.vv.listener/InitialSetup.groovy</code> to the step definition folders, such as:<pre className="pre codeblock"><code>Include/scripts/groovy/CucumberHooksDefinitions/InitialSetup.groovy{"\n"}Include/scripts/groovy/CucumberHooksDefinitions/SetupTestListener.groovy</code></pre></div></li><li className="li"><div className="p">Add glue to these hooks in your Cucumber runner as well:<pre className="pre codeblock"><code>glue = ['stepDefinitionPackage1', 'Include/scripts/groovy/CucumberHooksDefinitions', 'otherStepDefinitionPackages']</code></pre></div></li><li className="li"><div className="p">For other Cucumber elements that are not executed via the Cucumber runner, you can add glue in setup steps like this:<pre className="pre codeblock"><code>@BeforeTestCase{"\n"}def beforeTestCase(TestCaseContext context) {"{"}{"\n"}{"  "}CucumberGlueGenerator.addDefaultPackages();{"\n"}{"  "}// or{"\n"}{"  "}CucumberKW.GLUE = ['&lt;all the step definition packages&gt;']{"\n"}{"}"}{"\n"}</code></pre></div></li></ul></div></div>
